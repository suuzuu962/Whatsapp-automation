Your existing repository is actually a reasonable starting point because much of the WhatsApp, CRM, inbox, flow, automation, and human-side plumbing is already conceptually there. The biggest work is to add a properly designed agent runtime between the incoming WhatsApp message and the existing business actions.

The order I would personally follow is:

Study Meta WhatsApp API — understand the channel.
Study AI tool/function calling — understand how AI performs real actions.
Study context/state/memory — understand multi-turn conversations.
Study human-in-the-loop — connect AI with your existing inbox.
Study prompt injection and authorization — design security before exposing tools.
Design the agent runtime architecture.
Then map the exact existing repo files where each layer should be inserted.
Only after that choose Gemini/OpenAI/Claude and start coding.

That last part is important: I don't think your next step should be blindly integrating an LLM. The next useful step is to take the actual repository architecture you have and produce a concrete "current repo → target AI agent architecture" mapping: exactly what existing components can be retained, what new database tables are needed, what new services/modules should be created, and where the AI agent should sit in the existing webhook/flows/automation pipeline.  it goes something like this this is the last part check everything for this later we shall plan and start implementing things
